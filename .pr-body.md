🐛 Let a schemeless prefix name a hostname under either scheme

Fixes #132.

A rule like `{tool: fetch, command_prefix: "internal.example.com", action: deny}` validated at the build but never matched at runtime. The prefix comparison canonicalizes only when both sides pass `urlnorm.Canonical`, and that check requires an absolute http(s) scheme; a schemeless prefix therefore fell back to a lexical `strings.HasPrefix`, which an absolute URL never satisfies. Under a profile with `unmatched: allow`, the fetch the operator meant to deny ran. Worse than the issue stated: fetch is a read-only tool, and the policy permits an unmatched read-only call regardless of the `unmatched` setting, so no policy change contained the inert deny.

- A prefix that names no scheme is now a hostname rule: the call's own URL decides the scheme, so one hostname covers its http and https URLs alike. The host's spellings — case, trailing dot, default-port spellings — and its subdomains are judged the way an explicit-scheme prefix is judged.
- A prefix that names a scheme keeps holding it: the cleartext downgrade under an `https://` prefix still matches nothing.
- A prefix whose authority carries userinfo (`attacker@internal.example.com`) matches nothing rather than widening to the bare host behind the userinfo.
- A non-URL value keeps the lexical comparison, so command prefixes like `git status` behave as before.
- The `CommandPrefix` settings comment now states the hostname semantics.

## Semantics chosen

The issue named three options; this is option (c), schemeless-prefix matching in the perm matcher, over the schema-marker route. The review showed the schema route answers "what strings may this tool accept" (argument validity) with "what authority does this prefix denote" (permission semantics) — different contracts — and the route also required profile evolution in cli-registry. A hostname prefix means both HTTP and HTTPS; the call's URL decides which.

## Review guide

- `internal/urlnorm/urlnorm.go` — `CanonicalPrefix`, the new rule's grammar: host `[:port][/path]`, no scheme, no userinfo.
- `perm/perm.go` — `matchesCommand`, where the hostname rule enters the comparison.
- `perm/prefix_test.go` — the behaviors above, pinned as tests.

## Validation

- `go test ./... -count=1` passes (one flaky timing test in `./wire`, `TestThePageBudgetFollowsTheQueueBytes`, fails under load and passes standalone on both this branch and base).
- `go vet ./...` clean. `gofmt -l` clean. `scripts/lint-prompts.sh` exit 0.
- The new tests fail on the base commit's matcher: every hostname case reports a miss before the fix.

## Out of scope

- An explicit-scheme prefix carrying userinfo (`https://attacker@internal.example.com`) still canonicalizes to the bare host — a pre-existing quirk in `Canonical`, not introduced here. Filed as #134.
- A `PrimaryArg` that names a nonexistent or non-string property passes construction unchecked; the schema compilation does not cross-check it. Filed as #135.
