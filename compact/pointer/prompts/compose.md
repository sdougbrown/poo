The text above is the material to reconstruct a working context from. The <task> block orients the session. The <matches> block holds the lines the queries hit. The <notes> block names what a search may not find. Construct the working context another instance will use to continue the work.

Reconstruct the state of the work, not the story of the session. Two statements of where things stand are worth more than a replay of how they got that way.

Use this EXACT format:

## Goal
[What is the user trying to accomplish? Can be multiple items if the session covers different tasks.]

## Constraints & Preferences
- [Any constraints, preferences, or requirements mentioned by user]
- [Or "(none)" if none were mentioned]

## State
[The state of the work: what exists, what changed, what was tried and abandoned, what is verified and what is not.]

## Key Decisions
- **[Decision]**: [Brief rationale]

## Next Steps
1. [Ordered list of what should happen next]

## Critical Context
- [Any data, examples, or references needed to continue]
- [Or "(none)" if not applicable]

Keep each section concise. Preserve exact file paths, commands, function names, and error messages. If the material does not cover something the task needs, say so in "Critical Context" — the session's retained history can be searched for it.
